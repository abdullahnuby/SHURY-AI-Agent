# V22.8.1 Verification

Layer 5 acceptance gate:

1. Experiences persist once per run and survive process restarts.
2. Failed runs can produce contrastive lessons tied to success/failure evidence.
3. Reflections are stored only as bounded advisory lessons; they do not grant permissions.
4. Repeated verified workflows can create candidate skills, but candidates never auto-activate without explicit evidence gates.
5. Replay is counterfactual and never executes side-effecting tools.
6. Promotion requires repeated verified success, contextual/independent evidence, positive replay benefit, and zero recorded regressions.
7. An active evolving skill can be rolled back to candidate status without deleting evidence.
8. Full regression and real-user acceptance must be green before release.

9. Durable experience goals/task signatures redact credential-like values; legacy success-only reflection lessons are retired without deleting evidence.
10. Real-user CLI commands for learning status/learning/evolve/rollback/benchmark dispatch to their handlers.
11. Learned workflows preserve step dependencies and normalize argument-specific triggers into task-family signatures.

12. Real-user failure→success learning produces contrastive guidance tied to both trajectories.
13. Legacy reflection lessons without failed-step evidence are retired on manager initialization.
14. Self-improvement benchmark passes all checks without modifying deployment state.
