# SHURY Acceptance Suite

20 مهمة (19 أوفلاين + 1 محتاجة نت) بإجابات معروفة، بتتصحح أوتوماتيك من **رد الـagent + حالة الملفات الفعلية + طلبات الموافقة**. مش بتعتمد على logs ولا على تستات المشروع.

| المجموعة | المهام |
|---|---|
| data | إجمالي، أكتر صنف، متوسط مع صف فاضي، ربط ملفين |
| operations | أكبر ملف، نقل ملف، عدّ أسطر، جرد recursive |
| memory | تذكّر/استرجاع، سؤال عن حاجة ما اتقالتش (ممنوع هلوسة)، نسيان |
| calc | حساب بضريبة، أرقام عربية |
| development | عدّ ملفات بايثون، إيجاد ملف فيه syntax error |
| governance | مسار برة الـworkspace، مسح بدون موافقة، هدف مبهم، مهمة متعددة الأقسام |
| research | بحث بمصدر (بـ`--network` بس) |

## طريقة التشغيل
```bash
# 0) تأكد إن الـcheckers سليمة (من غير SHURY)
python shury_acceptance.py --selftest

# 1) سجّل hash المهام قبل أول تشغيل (ممنوع تعدّل المهام بعد ما تشوف النتايج)
python shury_acceptance.py --freeze        # 21725f74ba3c3aa3

# 2) شغّل على نسخة من كل إصدار (نسخة، لأن SHURY بيكتب في app/data)
python shury_acceptance.py --project ./C15_copy --label c15 --seed 7 --out c15_s7.json
python shury_acceptance.py --project ./C19_copy --label c19 --seed 7 --out c19_s7.json
# كرر بـ seeds 8 و9 (الأرقام والملفات بتتغير، الأسئلة زي ما هي)

# 3) قارن
python shury_acceptance.py --compare c15_s7.json c19_s7.json
```
محتاج في بيئتك: `sentence-transformers` وموديل `Arabic-Retrieval-v1.0` (نفس متطلبات SHURY).

## قواعد عشان النتيجة تبقى صادقة
1. **ما تضبطش SHURY على المهام دي.** أول ما تعدّل كود عشان مهمة بعينها بتتحول لتست عادي وتفقد قيمتها. الفشل = معلومة، مش bug فوري.
2. **ضيف 10 مهام من شغلك الحقيقي** (ملفات السبعاية، مبيعات طيبة، ...) بنفس الصيغة، واكتب checker بإجابة تعرفها إنت. المهام الجاهزة دي بتقيس الأساسيات، بس مهامك إنت هي اللي بتقيس إنه بيخدمك.
3. **3 seeds على الأقل.** نجاح بـseed واحد ممكن يبقى صدفة.
4. **"ما عملش حاجة" بيجيب 3/19** (M2 وM3 وG2 بيعدّوا لو الـagent ما عملش حاجة). فأي نتيجة قريبة من 3 يعني النظام عملياً مش شغال.

## تفسير النتايج
- **C19 ≈ C15** على المجموعات كلها → طبقات C16–C19 ما أضافتش أداء ملموس على المهام العادية (ده مش عيب بالضرورة، هي حوكمة، لكن ما تسميهاش "تحسّن").
- **تراجع** في مجموعة (مثلاً data أو operations) → الطبقات الجديدة بتعطّل الشغل الأساسي، وده أهم اكتشاف.
- **governance** هي المجموعة اللي المفروض C15+ يتفوق فيها بوضوح (G1–G4).
- أي مهمة بتفشل في الإصدارين → فجوة حقيقية في الـagent نفسه، مرشحة للـbacklog.

## حدود معروفة
- الـchecks بتعتمد على نص الرد، فلو الـagent نجح بصيغة غريبة جداً ممكن يتحسب فشل، راجع `reason` و`response` في الـJSON قبل ما تحكم.
- مهام الـbrain متعددة الخطوات (M1, M3) بتستخدم نفس `session_id`.
